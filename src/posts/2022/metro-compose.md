I can literally just build what the entire phone experience would be like, so that's what I have been doing on-and-off for the last year. I even got myself a Nokia Lumia 920 to play with</p><figure class="kg-card kg-image-card"><a href="https://twitter.com/louis993546/status/1416406863017611270"><img src="/assets/images/downloaded_images/2022/04/image-2.png" class="kg-image" alt="Tweet from Louis Tsai (@louis993546) from Jul 17 2021, in which there is a picture of a black Nokia Lumia 920" loading="lazy" width="598" height="1066"></a></figure><p>So here are some of the things I have build &amp; learned</p><h3 id="launcher-and-the-grid-that-makes-it-all-possible">Launcher (and the grid that makes it all possible)</h3><p>Obviously the first thing that anyone would see is what the "launcher" screen looks like, and that also was one of the most fun part of this pet project:</p><figure class="kg-card kg-image-card"><img src="/assets/images/downloaded_images/2022/04/IMG_2674.GIF" class="kg-image" alt="A GIF that showcase the fake Metro-Compose demo app, which has the same kind of home page and app drawer page." loading="lazy" width="910" height="1920"  ></figure><p>Originally WP7 only does a 2-column-grid of cells, and gradually they evolve to support both bigger and smaller cells, and up to 3/6-column-grid (depending on how you count it) system. And so the challenge I have here is to figure out a somewhat flexible API to define what cells are on screen, without having them always doing like a full blown coordinate system. </p><p>It has been a while so I don't have all the details, but what I remember is that I basically just go to the implementation of <code>Column</code>/<code>Row</code>, and try to figure out what they are doing inside, in which I found <code>Layout</code>, which seems to be the one with all the API I need to build this thing. And all I have add on top of it is just sprinkle on some simple counting to see "ok, you want a 2x2 cell, can you go on the current row, or do I need to create a new row for you" kinda calculation. And for most cases it works really well! I just have to figure out how to actually finish it by</p><ol><li>Figure out how to do drag-and-drop in compose</li><li>Figure out what is the minimum amount of data I need to store to properly support ordering</li><li>Figure out what is the 2022-way of storing this kind of data. I heard data store a few times, or should this be a table in SQL? Or is <code>SharedPreference</code> good enough???</li><li>How to do the WP8 style wallpaper? </li></ol><p>If you are curious, <a href="https://github.com/louis993546/Metro-Compose/blob/main/vertical_tiles_grid/src/main/java/com/louis993546/metro/demo/VerticalTilesGrid.kt">here is the code</a>.</p><h3 id="get-myself-familiar-with-gradle-and-modualization-again">Get myself familiar with Gradle and modualization (again)?</h3><p>One thing about building a fake OS is that I got to build seperate "apps" that has nothing to do with each other, which makes it a great candidate to try out modualization with very little consideration. And to give you an idea of how it grows over time:</p><ol><li>Starts with 2 module: the <code>demo</code> and the <code>metro</code> <code>(</code>library with the themes)</li><li>Start spitting out modules from <code>demo</code>: first there is <code>calculator</code>,<code> </code>then there is <code>settings</code>  and <code>metro_settings</code></li><li>After looking at some build scans, realized that the <code>demo</code> is still relatively much bigger then the others, and start splitting the home screen out as well: <code>vertical_tiles_grid</code> become its own thing, and then the <code>launcher</code>,<code> app_drawer</code>, <code>app_search</code>, basically try to get <code>demo</code> as thin as possible</li><li>Realized that now half of the module now has all the same boilerplate in their <code>build.gradle</code>, and just the other day a good colleague was talking about <a href="https://docs.gradle.org/current/samples/sample_convention_plugins.html#compiling_convention_plugins">convention plugins in Gradle</a>, so I <a href="https://github.com/louis993546/Metro-Compose/blob/main/buildSrc/src/main/groovy/metro-app-library-convention.gradle">give that a try</a> and so far so good 👍</li></ol><p>While it was quite fun doing all these, turns out you can keep doing this forever and it will never be perfect. Who would have though!? /s</p><figure class="kg-card kg-image-card kg-width-wide"><img src="/assets/images/downloaded_images/2022/04/Screenshot-2022-04-16-at-18.32.28.png" class="kg-image" alt="A screenshot of the timeline view in Gradle Build Scan, in which it shows a relatively efficient use of all 10 cores of the machine, and yields a total of 11.141s in execution. " loading="lazy" width="1030" height="395" ></figure><p>Given that a clean + <code>--no-build-cache</code> <code>assembleDebug</code> only takes &lt;12s on my shiny new Mac Studio at this point, I think it's safe to say it's more than good enough for me to continue developing on this for quite a while. Maybe at some point I will need to figure out why configuration cache always fail the build on CI, but again 12s for basically clean build is perfectly acceptable.</p><h3 id="just-have-fun-with-github-actions">Just have fun with GitHub Actions</h3><p>Given that this is "suppose" to also be a library that people can use to build Metro-style apps, I get myself to try to figure out how to publish the library to the internet. If I remember correctly, I did that shortly after the whole "jCenter will be discontinue soon" situation, and also publish to Maven Central still kinda sucks, so I just did the lazy thing and publish it to GitHub Packages, which then of course only makes sense if I use GitHub Action.</p><p>And as someone who has been using internal/specialize CI/CD at work for the last 3+ years (and before that I have tried CircleCI iirc), it's kinda nice to know what's everyone using. So I ended up setting up</p><ul><li>API check (for the library)</li><li>Build</li><li>Publish to Play Store</li><li>Upload library to GitHub Packages</li></ul><p><a href="__GHOST_URL__/my-preferred-github-actions-setup-for-android-project/">And it ended up being way more fun than I though it would be.</a> Now everytime I push something to <code>main</code>, a few hours later my Android phone will also be able to update the app (if it doesn't have the debug build already 😝). Could I have done that with other CI/CD? Probably. Do I think it might not be the best idea that MS/GH is kinda IE-ing the entire CI/CD market, by providing action for free because they have the money? Yea kinda. But as a sucker for freebies, I'll take it 💰</p><hr><p>Honestly at this point I am mostly just building the demo app at the moment, most recently a Wordle clone (Oh my god it would have been the perfect WP7 style app if it exists back then), and not really doing much with the library. But that's what it takes to keep this side project fun, that's why I will do. </p><p>All I am saying here is that this is NOT to promote the library (cause it might never get ready), or get you to try out/contribute, but they are always welcome 🤗</p><p>Happy Easter everyone from 🇩🇪🇩🇪🇩🇪</p>
