<p>This article will tell you everything you need to know to deal with all those crazy version rules. Everything will come with source (a.k.a. answers on StackOverflow) if necessary.</p><ol><li>minSdkVersion ≤ targetSdkVersion (dah)</li><li><a href="https://medium.com/google-developers/picking-your-compilesdkversion-minsdkversion-targetsdkversion-a098a0341ebd">targetSdkVersion ≤ compileSdkVersion</a></li><li><a href="https://stackoverflow.com/a/38072371/2384934">support libraries version = compileSdkVersio</a>n</li><li><a href="https://stackoverflow.com/a/24523113/2384934">compileSdkVersion ≤ buildToolsVersion</a></li><li>support libraries version ≤ buildToolsVersion (by combining no. 3 and no. 4)</li><li><a href="https://developer.android.com/studio/releases/gradle-plugin.html">click and scroll down to see the mapping between Gradle Plugin version and Gradle version</a></li></ol><p>TL;DR:</p><ol><li>minSdkVersion ≤ targetSdkVersion = support libraries version = compileSdkVersion ≤ buildToolsVersion</li><li>Android Gradle Plugin depends on the Gradle version</li></ol><p>Remark:</p><ol><li>even though targetSdkVersion can be older than support libraries version &amp; compileSdkVersion, <a href="https://medium.com/google-developers/picking-your-compilesdkversion-minsdkversion-targetsdkversion-a098a0341ebd">it does not seems to be recommended</a>, but I don’t know if there is anything that might break. If you have any experience/example/etc, let me know and I will update this document.</li><li><a href="https://developer.android.com/guide/topics/manifest/uses-sdk-element.html">the use of maxSdkVersion is generally discouraged</a></li><li>Gradle Plugin nor Gradle depends on Android Studio version from what I can see, but they generally comes together, and if you upgrade to a newer version of Android Studio it will usually ask if you want to upgrade The Gradle Plugin to the newer version.</li></ol>
